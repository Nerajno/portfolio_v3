# A Clearer Vue: From Fundamentals to Your First Single-Page App

*Part of the Vue Mastery Beginner Track Series - Covering Intro to Vue 3 & Real World Vue 3*

> **A note from the author:** This article is part of my ongoing series covering Vue Mastery's beginner track. It synthesizes concepts from both the "Intro to Vue 3 (Options API)" and "Real World Vue 3 (Composition API)" courses into a cohesive learning path. As I continue learning, I may refine and update sections. Feedback is always welcome—find me [@nerajno](https://twitter.com/nerajno).

Have you ever followed a Vue tutorial, nodded along to each concept, but still felt lost when it came time to build something real?

You understand refs. You get computed properties. But somehow, when you stare at a blank project, you don't know where to start or how it all fits together.

If that sounds familiar, this article is for you.

Instead of throwing isolated concepts at you like puzzle pieces, we'll walk through what each concept means, why it matters, and how it fits into a real project. By the end, you'll build a fully functioning Vue 3 SPA—"Vue Notes"—a minimal yet powerful notes application that stores your content in localStorage and demonstrates the full lifecycle of modern Vue development.

We'll cover both the Options API (great for understanding Vue's fundamentals) and the Composition API (the modern approach for scalable apps).

Let's start with clarity.

## Before You Start

To get the most out of this article, you should have:

- **Basic JavaScript knowledge** - Understanding of variables, functions, arrays, and objects
- **Familiarity with HTML/CSS** - You don't need to be an expert, but you should be comfortable with basic markup and styling
- **Node.js installed** - We'll be using npm to set up our project ([Download from nodejs.org](https://nodejs.org))

Don't have all of these? That's okay. Start where you are. The best way to learn is by doing, even if you stumble a bit.

**Time commitment:** Plan for 3-4 hours to work through this article and build the project. Take breaks. Let concepts sink in.

## Understanding Vue: Why Developers Gravitate Toward It

Vue is built on one key idea:

**A clear separation between state and the UI that renders it.**

You describe what you want the UI to look like, and Vue handles keeping it updated as your data changes. This means:

- Fewer manual DOM operations
- Less complex code
- A more intuitive mental model

At its core, Vue is about creating clear, reactive relationships between your data and the screen. Instead of manually updating the DOM every time something changes (like with vanilla JavaScript), Vue does the heavy lifting for you.

To see this in action, we'll start small.

## Your First Vue App: The "Aha" Moment

Let's start with the simplest possible Vue application using a CDN:

```html
<!DOCTYPE html>
<html>
<head>
  <title>My First Vue App</title>
  <script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
</head>
<body>
  <div id="app">
    <h1>{{ message }}</h1>
    <button @click="message = 'Hello, Vue!'">Click Me</button>
  </div>

  <script>
    const { createApp } = Vue

    createApp({
      data() {
        return {
          message: 'Welcome to Vue 3'
        }
      }
    }).mount('#app')
  </script>
</body>
</html>
```

That's it. You've created:
- A Vue app instance with `createApp()`
- A reactive data property in the `data()` function
- A dynamic template that updates when `message` changes
- An event handler that modifies the data

Click the button, and the UI updates automatically. This is the heart of Vue's reactivity—and once you see it work, it feels obvious.

> **Real Talk:** When I first saw this, I thought "This is magic!" But it's not—it's just Vue's reactive system tracking your data and efficiently updating only the parts of the DOM that changed. Once you internalize this, everything else makes sense.

## Two APIs, One Vue: Options vs Composition

Before we dive deeper, let's address something important: Vue 3 offers two ways to write components.

### Options API

The **Options API** organizes your component using well-defined options like `data`, `methods`, `computed`, and `mounted`:

```javascript
export default {
  data() {
    return {
      count: 0
    }
  },
  methods: {
    increment() {
      this.count++
    }
  },
  computed: {
    doubleCount() {
      return this.count * 2
    }
  },
  mounted() {
    console.log('Component is mounted!')
  }
}
```

**When to use it:**
- Learning Vue for the first time
- Building simpler applications
- Coming from a class-based programming background
- You prefer clear, structured organization

### Composition API

The **Composition API** uses functions and reactive references to build your component logic:

```javascript
import { ref, computed, onMounted } from 'vue'

export default {
  setup() {
    const count = ref(0)

    function increment() {
      count.value++
    }

    const doubleCount = computed(() => count.value * 2)

    onMounted(() => {
      console.log('Component is mounted!')
    })

    return { count, increment, doubleCount }
  }
}
```

**When to use it:**
- Building larger, more complex applications
- You want better TypeScript support
- You need to extract and reuse logic (composables)
- You're working on a production app

**For this article**, we'll learn both but focus on the Composition API for our final project, as it's the recommended approach for modern Vue development and what you'll see in most production codebases.

## Attribute Binding: Making HTML Dynamic

Vue's template syntax goes beyond simple text interpolation. You can bind HTML attributes dynamically using `v-bind` or its shorthand `:`.

```vue
<template>
  <div>
    <!-- Long form -->
    <img v-bind:src="imageUrl" v-bind:alt="imageAlt">

    <!-- Shorthand (preferred) -->
    <img :src="imageUrl" :alt="imageAlt">

    <!-- Binding classes -->
    <div :class="{ active: isActive, 'text-large': isLarge }">
      Content
    </div>

    <!-- Binding styles -->
    <div :style="{ color: textColor, fontSize: size + 'px' }">
      Styled text
    </div>
  </div>
</template>

<script setup>
import { ref } from 'vue'

const imageUrl = ref('/path/to/image.jpg')
const imageAlt = ref('Description')
const isActive = ref(true)
const isLarge = ref(false)
const textColor = ref('blue')
const size = ref(16)
</script>
```

**What you've learned:**
- `:attribute` binds JavaScript expressions to HTML attributes
- Class and style bindings have special object/array syntax
- The UI updates automatically when bound data changes

## Conditional Rendering: Showing and Hiding Content

Vue provides directives to conditionally render elements:

```vue
<template>
  <div>
    <!-- v-if removes/adds element from DOM -->
    <p v-if="inventory > 10">In Stock</p>
    <p v-else-if="inventory > 0">Almost Sold Out</p>
    <p v-else>Out of Stock</p>

    <!-- v-show toggles CSS display property -->
    <p v-show="showDetails">Product details here...</p>

    <button @click="showDetails = !showDetails">
      Toggle Details
    </button>
  </div>
</template>

<script setup>
import { ref } from 'vue'

const inventory = ref(8)
const showDetails = ref(false)
</script>
```

**v-if vs v-show:**
- `v-if` - Completely removes the element from the DOM (higher toggle cost)
- `v-show` - Just toggles CSS `display: none` (better for frequent toggling)

Use `v-if` when the condition rarely changes. Use `v-show` for frequent visibility toggles.

## List Rendering: Displaying Multiple Items

Rendering lists is a core pattern in any UI. Vue makes it clean with `v-for`:

```vue
<template>
  <div>
    <h2>Product Reviews</h2>
    <div v-if="reviews.length === 0">
      <p>No reviews yet.</p>
    </div>
    <ul v-else>
      <li v-for="review in reviews" :key="review.id">
        <strong>{{ review.name }}</strong> gave {{ review.rating }} stars
        <p>{{ review.comment }}</p>
      </li>
    </ul>
  </div>
</template>

<script setup>
import { ref } from 'vue'

const reviews = ref([
  { id: 1, name: 'Nerando', rating: 5, comment: 'Great product!' },
  { id: 2, name: 'Sarah', rating: 4, comment: 'Pretty good overall' }
])
</script>
```

**Critical rule:** Always include `:key` with a unique identifier. This helps Vue efficiently track which items changed, were added, or were removed. Never use the array index as the key in production apps—use unique IDs.

> **Stumbling Block:** Forgetting the `:key` attribute is one of the most common Vue mistakes. Your app might work, but you'll see warnings in the console and potentially weird bugs when the list changes.

## Event Handling: Responding to User Actions

Vue uses the `@` shorthand (or `v-on:`) to listen for DOM events:

```vue
<template>
  <div>
    <!-- Click events -->
    <button @click="addToCart">Add to Cart</button>
    <button @click="cart += 1">Quick Add</button>

    <!-- With event modifiers -->
    <form @submit.prevent="handleSubmit">
      <input @keyup.enter="search" v-model="query">
      <button type="submit">Search</button>
    </form>

    <!-- Mouse events -->
    <div
      @mouseenter="hovering = true"
      @mouseleave="hovering = false"
      :class="{ highlighted: hovering }"
    >
      Hover over me
    </div>
  </div>
</template>

<script setup>
import { ref } from 'vue'

const cart = ref(0)
const query = ref('')
const hovering = ref(false)

function addToCart() {
  cart.value++
  console.log('Added to cart!')
}

function handleSubmit() {
  console.log('Form submitted with:', query.value)
}

function search() {
  console.log('Searching for:', query.value)
}
</script>
```

**Useful event modifiers:**
- `.prevent` - Calls `event.preventDefault()`
- `.stop` - Calls `event.stopPropagation()`
- `.once` - Event triggers only once
- `.enter`, `.tab`, `.esc` - Key-specific listeners

## Class and Style Binding: Dynamic Styling

Vue provides powerful ways to bind classes and styles dynamically:

```vue
<template>
  <div>
    <!-- Object syntax for classes -->
    <div
      :class="{
        active: isActive,
        'text-danger': hasError,
        'font-bold': isBold
      }"
    >
      Dynamic classes
    </div>

    <!-- Array syntax for classes -->
    <div :class="[baseClass, isActive ? activeClass : '']">
      Array classes
    </div>

    <!-- Inline style binding -->
    <div :style="{
      color: productColor,
      fontSize: fontSize + 'px',
      backgroundColor: bgColor
    }">
      Dynamic styles
    </div>

    <!-- Multiple style objects -->
    <div :style="[baseStyles, overrideStyles]">
      Combined styles
    </div>
  </div>
</template>

<script setup>
import { ref, computed } from 'vue'

const isActive = ref(true)
const hasError = ref(false)
const isBold = ref(true)
const productColor = ref('#3498db')
const fontSize = ref(16)
const bgColor = ref('#ecf0f1')

const baseClass = 'container'
const activeClass = 'container-active'

const baseStyles = ref({ padding: '20px' })
const overrideStyles = ref({ margin: '10px' })
</script>
```

This pattern is particularly useful for:
- Theme switching
- Component states (loading, error, success)
- Responsive designs
- User preferences

## Computed Properties: Smart Derived State

Computed properties automatically recalculate when their dependencies change, and they're cached for performance:

```vue
<template>
  <div>
    <p>First Name: <input v-model="firstName"></p>
    <p>Last Name: <input v-model="lastName"></p>
    <p>Full Name: {{ fullName }}</p>
    <p>Initials: {{ initials }}</p>

    <h3>Cart ({{ cartItemCount }} items)</h3>
    <p>Total: ${{ cartTotal }}</p>
  </div>
</template>

<script setup>
import { ref, computed } from 'vue'

const firstName = ref('Nerando')
const lastName = ref('Johnson')

// Computed properties
const fullName = computed(() => {
  return `${firstName.value} ${lastName.value}`
})

const initials = computed(() => {
  return `${firstName.value[0]}${lastName.value[0]}`
})

const cartItems = ref([
  { name: 'Socks', price: 10, quantity: 2 },
  { name: 'Shirt', price: 25, quantity: 1 }
])

const cartItemCount = computed(() => {
  return cartItems.value.reduce((total, item) => total + item.quantity, 0)
})

const cartTotal = computed(() => {
  return cartItems.value.reduce((total, item) => {
    return total + (item.price * item.quantity)
  }, 0)
})
</script>
```

**Why use computed over methods?**
- Computed properties are cached based on their dependencies
- They only recalculate when dependencies change
- Methods run every time they're called in the template

Use computed for derived data. Use methods for actions and side effects.

## Components: Building Reusable UI Pieces

Components are the building blocks of Vue applications. They encapsulate HTML, CSS, and JavaScript into reusable pieces:

```vue
<!-- ProductDisplay.vue -->
<template>
  <div class="product-display">
    <img :src="product.image" :alt="product.name">
    <h2>{{ product.name }}</h2>
    <p>{{ product.description }}</p>
    <p class="price">${{ product.price }}</p>
    <button
      @click="$emit('add-to-cart', product.id)"
      :disabled="!product.inStock"
    >
      {{ product.inStock ? 'Add to Cart' : 'Out of Stock' }}
    </button>
  </div>
</template>

<script setup>
defineProps({
  product: {
    type: Object,
    required: true
  }
})

defineEmits(['add-to-cart'])
</script>

<style scoped>
.product-display {
  border: 1px solid #ddd;
  padding: 20px;
  border-radius: 8px;
}

.price {
  font-size: 24px;
  font-weight: bold;
  color: #2c3e50;
}
</style>
```

**Using the component:**

```vue
<template>
  <div>
    <ProductDisplay
      v-for="product in products"
      :key="product.id"
      :product="product"
      @add-to-cart="addToCart"
    />
  </div>
</template>

<script setup>
import { ref } from 'vue'
import ProductDisplay from './components/ProductDisplay.vue'

const products = ref([
  {
    id: 1,
    name: 'Vue Socks',
    price: 10,
    image: '/socks.jpg',
    description: 'Comfortable Vue-themed socks',
    inStock: true
  }
])

function addToCart(productId) {
  console.log('Adding product to cart:', productId)
}
</script>
```

**Component communication patterns:**
- **Props down** - Parent passes data to child via props
- **Events up** - Child emits events to notify parent of actions
- **Slots** - Parent provides content that child renders

This unidirectional data flow keeps your app predictable and easier to debug.

## Forms and v-model: Two-Way Data Binding

Forms are everywhere in web apps. Vue's `v-model` makes form handling elegant:

```vue
<template>
  <form @submit.prevent="submitReview">
    <h3>Leave a Review</h3>

    <!-- Text input -->
    <label for="name">Name:</label>
    <input id="name" v-model="review.name" required>

    <!-- Textarea -->
    <label for="comment">Review:</label>
    <textarea id="comment" v-model="review.comment" required></textarea>

    <!-- Radio buttons -->
    <label>Rating:</label>
    <div>
      <input type="radio" id="5-stars" value="5" v-model="review.rating">
      <label for="5-stars">5 Stars</label>

      <input type="radio" id="4-stars" value="4" v-model="review.rating">
      <label for="4-stars">4 Stars</label>

      <input type="radio" id="3-stars" value="3" v-model="review.rating">
      <label for="3-stars">3 Stars</label>
    </div>

    <!-- Checkbox -->
    <input type="checkbox" id="recommend" v-model="review.recommend">
    <label for="recommend">Would you recommend this product?</label>

    <!-- Select dropdown -->
    <label for="source">How did you hear about us?</label>
    <select id="source" v-model="review.source">
      <option value="">Select one</option>
      <option value="friend">Friend</option>
      <option value="social">Social Media</option>
      <option value="search">Search Engine</option>
      <option value="ad">Advertisement</option>
    </select>

    <button type="submit">Submit Review</button>
  </form>

  <!-- Preview -->
  <div v-if="review.name">
    <h4>Preview:</h4>
    <pre>{{ review }}</pre>
  </div>
</template>

<script setup>
import { reactive } from 'vue'

const review = reactive({
  name: '',
  comment: '',
  rating: null,
  recommend: false,
  source: ''
})

function submitReview() {
  console.log('Review submitted:', review)
  // Handle form submission
}
</script>
```

**v-model modifiers:**
- `.lazy` - Sync after change event instead of input
- `.number` - Automatically typecast to number
- `.trim` - Automatically trim whitespace

Example: `<input v-model.trim.lazy="username">`

## Composition API Deep Dive: The Modern Approach

Now that you understand the fundamentals, let's dive deeper into the Composition API—the recommended way to build production Vue 3 apps.

### setup() vs &lt;script setup&gt;

There are two ways to use the Composition API:

**Traditional setup():**
```vue
<script>
import { ref, computed } from 'vue'

export default {
  setup() {
    const count = ref(0)
    const doubled = computed(() => count.value * 2)

    function increment() {
      count.value++
    }

    return { count, doubled, increment }
  }
}
</script>
```

**Modern &lt;script setup&gt; (recommended):**
```vue
<script setup>
import { ref, computed } from 'vue'

const count = ref(0)
const doubled = computed(() => count.value * 2)

function increment() {
  count.value++
}
// Everything is automatically exposed to template
</script>
```

`<script setup>` is less verbose and has better performance. It's what we'll use in our project.

### Reactive References: ref() vs reactive()

Vue provides two ways to create reactive state:

**ref() - For primitive values (and objects):**
```javascript
import { ref } from 'vue'

const count = ref(0)
const user = ref({ name: 'Nerando', age: 30 })

console.log(count.value) // 0
console.log(user.value.name) // 'Nerando'

count.value++
user.value.name = 'Sarah'
```

**reactive() - For objects only:**
```javascript
import { reactive } from 'vue'

const state = reactive({
  count: 0,
  user: { name: 'Nerando', age: 30 }
})

console.log(state.count) // 0 (no .value needed!)
console.log(state.user.name) // 'Nerando'

state.count++
state.user.name = 'Sarah'
```

**Which to use?**
- Use `ref()` for everything (simplicity and consistency)
- Or use `ref()` for primitives and `reactive()` for objects
- Never destructure `reactive()` objects (breaks reactivity)

For most developers, using `ref()` for everything is the clearest approach.

> **Stumbling Block:** Forgetting `.value` with refs is the #1 beginner mistake in Composition API. If something isn't reactive, check if you forgot `.value` first.

### Watchers: Reacting to Changes

Watchers let you perform side effects when reactive data changes:

```javascript
import { ref, watch } from 'vue'

const count = ref(0)
const user = ref({ name: 'Nerando', email: 'n@example.com' })

// Watch a single ref
watch(count, (newValue, oldValue) => {
  console.log(`Count changed from ${oldValue} to ${newValue}`)
})

// Watch multiple sources
watch([count, user], ([newCount, newUser], [oldCount, oldUser]) => {
  console.log('Either count or user changed')
})

// Watch object property (deep watch)
watch(
  () => user.value.email,
  (newEmail) => {
    console.log('Email changed to:', newEmail)
  }
)

// Deep watch entire object
watch(
  user,
  (newUser) => {
    console.log('User object changed:', newUser)
  },
  { deep: true }
)

// Immediate execution
watch(
  count,
  (val) => {
    console.log('Count is:', val)
  },
  { immediate: true } // Runs immediately on component mount
)
```

**Common use cases for watchers:**
- API calls when data changes
- LocalStorage persistence
- Validation
- Logging and analytics

## Lifecycle Hooks: Component Lifetime Events

Components go through a lifecycle. Vue provides hooks to run code at specific stages:

```vue
<script setup>
import { ref, onBeforeMount, onMounted, onBeforeUpdate, onUpdated, onBeforeUnmount, onUnmounted } from 'vue'

const data = ref(null)

onBeforeMount(() => {
  console.log('Before component is mounted to DOM')
})

onMounted(() => {
  console.log('Component is mounted!')
  // Perfect for:
  // - API calls
  // - DOM manipulation
  // - Setting up third-party libraries
  fetchData()
})

onBeforeUpdate(() => {
  console.log('Before component re-renders due to data change')
})

onUpdated(() => {
  console.log('Component re-rendered!')
  // Careful: Can cause infinite loops if not used correctly
})

onBeforeUnmount(() => {
  console.log('Before component is destroyed')
  // Clean up: timers, event listeners, subscriptions
})

onUnmounted(() => {
  console.log('Component is destroyed')
})

async function fetchData() {
  const response = await fetch('https://api.example.com/data')
  data.value = await response.json()
}
</script>
```

**Most commonly used:**
- `onMounted()` - Fetch data, set up event listeners
- `onUnmounted()` - Clean up to prevent memory leaks

## Composables: Reusable Logic

Composables are the Composition API's killer feature—reusable functions that encapsulate reactive logic:

```javascript
// composables/useCounter.js
import { ref } from 'vue'

export function useCounter(initialValue = 0) {
  const count = ref(initialValue)

  function increment() {
    count.value++
  }

  function decrement() {
    count.value--
  }

  function reset() {
    count.value = initialValue
  }

  return { count, increment, decrement, reset }
}
```

**Using the composable:**
```vue
<script setup>

</script>

<template>
  <div>
    <p>Count: {{ count }}</p>
    <button @click="increment">+</button>
    <button @click="decrement">-</button>
    <button @click="reset">Reset</button>
  </div>
</template>
```

**More practical example - localStorage composable:**

```javascript
// composables/useLocalStorage.js
import { ref, watch } from 'vue'

export function useLocalStorage(key, defaultValue) {
  // Initialize from localStorage or use default
  const storedValue = localStorage.getItem(key)
  const data = ref(storedValue ? JSON.parse(storedValue) : defaultValue)

  // Watch for changes and persist to localStorage
  watch(
    data,
    (newValue) => {
      localStorage.setItem(key, JSON.stringify(newValue))
    },
    { deep: true }
  )

  return data
}
```


## Single-Page Applications: Modern Web Apps

Traditional websites reload the entire page on every navigation. Single-Page Applications (SPAs) work differently:

**Traditional Multi-Page App:**
```
User clicks link → Browser requests new HTML → Server sends new page → Full page reload
```

**Single-Page Application:**
```
User clicks link → JavaScript intercepts → Component swaps → No reload!
```

**Benefits:**
- Instant navigation (feels like a native app)
- Preserved state between pages
- Better user experience
- Reduced server load

**Trade-offs:**
- Initial load can be slower (more JavaScript)
- SEO requires special handling (or use SSR with Nuxt)
- Browser back button needs special handling (Vue Router does this)

Vue Router makes building SPAs straightforward.

### Notes Management Composable: useNotes()

The brain of our app:

```javascript
// composables/useNotes.js
import { computed } from 'vue'
import { useLocalStorage } from './useLocalStorage'

export function useNotes() {
  // All notes stored in localStorage
  const notes = useLocalStorage('vue-notes', [])

  // Generate unique ID
  function generateId() {
    return Date.now() + Math.random().toString(36).substr(2, 9)
  }

  // Add new note
  function addNote(note) {
    const newNote = {
      id: generateId(),
      title: note.title,
      content: note.content,
      tags: note.tags || [],
      createdAt: new Date().toISOString(),
      updatedAt: new Date().toISOString()
    }
    notes.value.push(newNote)
    return newNote
  }

  // Get single note by ID
  function getNote(id) {
    return notes.value.find(note => note.id === id)
  }

  // Update existing note
  function updateNote(id, updates) {
    const index = notes.value.findIndex(note => note.id === id)
    if (index !== -1) {
      notes.value[index] = {
        ...notes.value[index],
        ...updates,
        updatedAt: new Date().toISOString()
      }
      return notes.value[index]
    }
    return null
  }

  // Delete note
  function deleteNote(id) {
    const index = notes.value.findIndex(note => note.id === id)
    if (index !== -1) {
      notes.value.splice(index, 1)
      return true
    }
    return false
  }

  // Search notes
  function searchNotes(query) {
    if (!query) return notes.value

    const lowerQuery = query.toLowerCase()
    return notes.value.filter(note =>
      note.title.toLowerCase().includes(lowerQuery) ||
      note.content.toLowerCase().includes(lowerQuery) ||
      note.tags.some(tag => tag.toLowerCase().includes(lowerQuery))
    )
  }

  // Get all unique tags
  const allTags = computed(() => {
    const tagSet = new Set()
    notes.value.forEach(note => {
      note.tags.forEach(tag => tagSet.add(tag))
    })
    return Array.from(tagSet).sort()
  })

  // Sort notes
  function sortNotes(sortBy = 'updatedAt', order = 'desc') {
    const sorted = [...notes.value].sort((a, b) => {
      if (sortBy === 'title') {
        return order === 'asc'
          ? a.title.localeCompare(b.title)
          : b.title.localeCompare(a.title)
      }
      // Date sorting
      const dateA = new Date(a[sortBy])
      const dateB = new Date(b[sortBy])
      return order === 'asc' ? dateA - dateB : dateB - dateA
    })
    return sorted
  }

  return {
    notes,
    addNote,
    getNote,
    updateNote,
    deleteNote,
    searchNotes,
    sortNotes,
    allTags
  }
}
```

**What this demonstrates:**
- Centralized state management
- CRUD operations (Create, Read, Update, Delete)
- Computed properties for derived data
- Array manipulation methods
- Automatic persistence via useLocalStorage

Any component can now import `useNotes()` and have full access to all note operations.

```vue
})

const emit = defineEmits(['save', 'cancel'])

const router = useRouter()

const formData = ref({
  title: props.initialNote.title,
  content: props.initialNote.content,
  tags: [...(props.initialNote.tags || [])]
})

const tagInput = ref(formData.value.tags.join(', '))

// Watch tag input and parse tags
watch(tagInput, (newValue) => {
  formData.value.tags = newValue
    .split(',')
    .map(tag => tag.trim())
    .filter(tag => tag.length > 0)
})

function removeTag(index) {
  formData.value.tags.splice(index, 1)
  tagInput.value = formData.value.tags.join(', ')
}

function handleSubmit() {
  emit('save', {
    title: formData.value.title,
    content: formData.value.content,
    tags: formData.value.tags
  })
}

function handleCancel() {
  if (emit('cancel')) {
    // If parent handled cancel, do nothing
    return
  }
  // Default behavior: go back
  router.go(-1)
}
</script>
```
